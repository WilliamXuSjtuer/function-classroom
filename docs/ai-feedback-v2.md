# 课堂反馈修复：teaching-v2.0

根据第 6 班课堂导出记录修复反馈与评价问题。原 Excel 和历史消息保持原样，新评价记录使用 `teaching-v2.0`。

## 修复范围

- 判断采用数学上充分的理由，不要求逐字复述参考答案。指出定义域不同并否定“同一个函数”，可以构成有效纠正；本题通过不以整课所有检查项达标为前提。
- 判断阶段保留针对学生新回答的反馈。前两次追问不再被固定提示覆盖，仍由服务端在第三次未完成时给出明确说明。
- 讲解区分已满足、待补充、需修正与待复核。问题按细项分别计数，解决后的细项清除连续追问计数，累计追问、补充说明、明确纠错各自保留。
- 函数概念的四条原始审核标准细分为十二个要点，固定编号，跨轮累计学生证据。已有正确证据不能仅因本轮未重复而撤销；明确的新错误才撤销相应细项。
- 原始审核标准完全匹配时才使用内置细分，教师改过的标准采用教师文本。自定义标准可每行写一个独立要点，每项最多20行，保存及发布时校验。旧已发布的超长标准保留全文作为单项评价，不丢弃行。
- 文字证据必须逐字出现在对应学生消息中。图像证据必须对应本次发送的图片或已有核验记录。本题通过和修正只使用本题判断阶段学生消息；智能体消息和其他例题不能充作依据。
- 评价说明由核验后的字段生成，不保存模型自由生成的达标说明。无法核验的证据触发一次重新评价；仍有疑问时进入待复核，不更新学生进度或增加提示次数。
- 格式错误自动重试一次，最多两次模型请求，共享单次评价超时限制。连续失败保留学生原文，显示系统未能评价，不当作学生答错。
- 学生与教师端区分系统评价状态和学习任务状态。导出新增细项证据表、证据引用、模型请求次数、复核标记，以及补充说明次数。

## 兼容与数据分析

无数据库表迁移。旧消息、旧课时快照和旧评价保持不变；旧的粗粒度追问统计继续读取，新反馈开始累计细项记录。原始四张工作表保留，新增列追加在右侧，增加一张细项证据表。学生接口不提供细项审核标准。

`pending` 表示课堂切换时任务未完成。`failed` 表示系统未能评价；`review` 表示证据待复核。不能将这三类直接记成学生知识错误。提交次数包含真实提交，自动重试不会新增学生作答。模型请求次数单独记录在成功返回的评价中；连续失败的原因记录在原始对话错误列。

本次没有重新评价或覆盖正式课堂历史，也没有修改教师已发布的课时。新版细项证据从下一次正常提交开始积累。

提交新回答只更新处理状态和提交次数。已有达标记录不会因为新回答遇到系统失败或证据待复核而被撤销；新的有效评价才会更新学习状态。

## 验证方式

- `npm test`：本地模型接口契约测试与课堂 HTTP 集成测试，不调用真实模型。
- `npm run typecheck`、`npm run build`：前后端类型检查与生产构建。
- `npm run test:ai`：显式运行六个匿名化教学场景，使用本地配置的 DeepSeek 密钥，会产生模型调用费用；不读写正式课堂数据库。结果写入忽略跟踪的 `artifacts/ai-review-v2.json`。

2026-11-16 首轮真实 `deepseek-flash` 检查六个场景全部通过，每个场景一次请求：定义域不同的充分理由、只说判断正确、补充“同时满足”后的追问、接纳口误修正、完整解释根式限制、识别一对多的错误。该结果是小样本回归验证，不是总体准确率或学习效果证明。

最终验证：20项自动测试全部通过，前后端类型检查和生产构建通过。构建仍有原有的 JavaScript 单包超过500KB提示（约680KB，gzip约209KB）。本轮未增加浏览器视觉或平板触控验收。

50人本地模拟并发复测：50条消息全部接收并获得反馈，无重复消息，提交P95为261毫秒，全部模拟反馈492毫秒，阶段切换30毫秒，所有学生均读取到新阶段。使用延迟250毫秒的模拟评价器，这些数值不代表真实模型或云端吞吐。

## Standards

审查发现两项实际问题，均已修复并复核：

- 新提交不应先重置已有学习状态。现在系统失败或待复核只影响评价状态，已有达标保留；HTTP回归覆盖讲解及两道例题。
- 教师可填写的独立标准数量与模型结构上限不一致。现在保存、发布及模型结构共用20项上限，旧已发布的超长标准按全文保留兼容。

启发式结构建议：无。标准线两项问题已解决，无剩余阻断。
