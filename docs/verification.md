## 测试覆盖

1. 教师与学生权限、草稿发布门槛、学生接口答案字段隔离、阶段权限与版本冲突。
2. 学号前导零、重复名册拒绝、密码重置使旧会话失效。
3. 消息幂等提交、手写图片归属、跨学生图片访问拒绝、Excel和图片附件导出。
4. 教师切换阶段后保留待补，晚到模型反馈不覆盖新阶段进度。
5. 正常完成讲解和全部例题后不会被误标待补。
6. 同一问题先追问两轮，再明确纠错；理由必填；首次判断不被后续修改覆盖。
7. 模型失败保留原文；重试不制造重复作答；有更新作答时禁止重试旧失败消息。
8. 补做关联原课堂，补做期间新导入的学生不会被加入没有原任务的补做。
9. 模型请求携带图片与早期评价证据，移除无法关联原文的达标评价；限制图像总量；讲解阶段不提供预设例题答案。

## 模拟负载结果

通过本机 HTTP 服务、临时 SQLite 数据库和延迟250毫秒的模拟评价器运行，没有调用真实 DeepSeek。

| 指标 | 本次结果 |
| --- | --- |
| 同时提交学生数 | 50 |
| 成功接收消息 / 获得模拟评价 | 50 / 50 |
| 重复学生消息 | 0 |
| 提交确认 P50 / P95 | 235ms / 239ms |
| 全部模拟反馈完成 | 515ms |
| 教师阶段切换 | 31ms |
| 学生读取到新阶段 | 50 / 50 |

这是应用保存、状态同步和模拟反馈路径的结果，不是 DeepSeek 真实推理、模型队列吞吐或阿里云生产性能的测量。原始结果可通过重新运行 `npm run test:load` 写入 `artifacts/load-test.json`。

## Standards

没有发现违反仓库现有书面编码规范的情况。标准审查发现并完成修复的实际问题：

- 待补状态提前设置、达标后不能准确归零。
- 备课草稿可能在导航或远端版本更新时丢失。
- 长对话截断后，已有达标项可能因早期证据缺失而倒退。
- 图片上下文缺少总字节及张数预算。
- 审核确认未冻结被审核的课时版本。
- 旧失败消息重试可能覆盖较新的正确作答。

维护建议：后续可按认证、备课、课堂边界拆分 `server/app.ts` 的路由；这属于结构改进建议，不是本次功能阻断项。

标准线合计6项实际问题已修复、1项维护建议；原最严重问题为待补状态错误，已通过完整成功课堂的回归测试验证。

## Spec

需求审查发现并完成修复的偏差：

- 完整完成课堂的学生仍可能被误标待补。
- 学生端缺少自己的待补标记和逐题完成状态。
- 补做期间导入的新生可能错误加入补做，缺少原课堂任务关联。

需求线合计3项偏差已修复，原最严重问题为待补状态错误。复核未发现新的实质性需求问题。
